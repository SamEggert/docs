<Info>
  Los [planes Pro y Enterprise](https://mintlify.com/pricing?ref=docs-ci) incluyen verificaciones de CI para repositorios de GitHub.
</Info>

Usa las verificaciones de CI para analizar tu documentación en busca de errores y mostrar advertencias antes de la implementación. Las verificaciones de CI están configuradas para ejecutarse en commits a la rama de implementación que hayas configurado o en pull requests dirigidos a esa rama.

<div id="installation">
  ## Instalación
</div>

Para comenzar, sigue los pasos de la página de [GitHub](/es/deploy/github).

Para las GitHub Apps, puedes otorgar permisos únicamente a un repositorio. Te recomendamos hacerlo, ya que solo necesitamos acceso al repositorio donde se alojan tu documentación.

<div id="configuration">
  ## Configuración
</div>

Configura las comprobaciones de CI habilitadas para una implementación desde la página de [Add-ons](https://dashboard.mintlify.com/products/addons) de tu dashboard. Activa las comprobaciones que quieras ejecutar.

Al habilitar comprobaciones, puedes elegir ejecutarlas con nivel `Advertencia` o `Blocking`.

* Una comprobación con nivel `Advertencia` nunca mostrará un estado de fallo, incluso si hay errores o sugerencias.
* Una comprobación con nivel `Blocking` mostrará un estado de fallo si no se supera o si se sugieren cambios.

<div id="available-ci-checks">
  ## Comprobaciones de CI disponibles
</div>

<div id="broken-links">
  ### Enlaces rotos
</div>

Al igual que el [verificador de enlaces de la CLI](/es/create/broken-links#broken-links) en tu máquina local, comprobamos automáticamente tu documentación para detectar enlaces rotos.

Para ver los resultados de esta verificación, visita la página de resultados de checks de GitHub para un commit específico.

<div id="vale">
  ### Vale
</div>

[Vale](https://vale.sh/) es un linter de prosa de código abierto basado en reglas que admite varios tipos de documentos, incluidos Markdown y MDX.

Mintlify permite ejecutar Vale automáticamente en una comprobación de CI y mostrar los resultados como un estado de comprobación.

<div id="configuration">
  #### Configuración
</div>

Si tienes un archivo `.vale.ini` en el directorio raíz de content de tu implementación, usaremos automáticamente ese archivo de configuración. También usaremos automáticamente cualquier archivo de configuración en el `stylesPath` que especifiques.

Si no tienes un archivo de configuración de Vale, se cargará la configuración predeterminada automáticamente.

```mdx Default vale.ini configuration expandable
# Estilos de nivel superior
StylesPath = /app/styles
MinAlertLevel = suggestion
IgnoredScopes = code, tt, img, url, a
SkippedScopes = script, style, pre, figure, code

# Vocabularios
Vocab = Mintlify

# Esto es requerido ya que Vale no soporta oficialmente MDX
[formats]
mdx = md

# Soporte para MDX
[*.mdx]
BasedOnStyles = Vale
Vale.Terms = NO # Aplica reglas de capitalización muy estrictas, mantener desactivado

# `import ...`, `export ...`
# `<Component ... />`
# `<Component>...</Component>`
# `{ ... }`
TokenIgnores = (?sm)((?:import|export) .+?$), \
(?<!`)(<\w+ ?.+ ?\/>)(?!`), \
(<[A-Z]\w+>.+?<\/[A-Z]\w+>)

# Excluir:
# `<Component \n ... />`
BlockIgnores = (?sm)^(<\w+\n .*\s\/>)$, \
(?sm)^({.+.*})

CommentDelimiters = {/*, */}
```

<Warning>
  Tenga en cuenta que, por razones de seguridad, no podemos admitir ningún `stylesPath` absoluto ni ningún `stylesPath` que incluya `..`. Use rutas relativas e incluya el `stylesPath` en su repositorio.

<div id="packages">
  #### Paquetes
</div>

Vale admite una variedad de [paquetes](https://vale.sh/docs/keys/packages) que puedes usar para detectar errores de ortografía y de estilo.
Cualquier paquete que incluyas en tu repositorio bajo el `stylesPath` correcto se instalará automáticamente y se usará en tu configuración de Vale.

Para los paquetes que no estén incluidos en tu repositorio, puedes especificar cualquiera del [registro de paquetes de Vale](https://vale.sh/explorer); se descargarán automáticamente y se utilizarán en tu configuración de Vale.

<Warning>
  Ten en cuenta que, por motivos de seguridad, no podemos admitir la descarga automática de paquetes que no provengan del [registro de paquetes de Vale](https://vale.sh/explorer).
</Warning>

<div id="vale-with-mdx">
  #### Vale con `MDX`
</div>

Vale no es compatible de forma nativa con `MDX`, pero el autor de Vale ha proporcionado una [extensión personalizada](https://github.com/errata-ai/MDX) para añadir compatibilidad.

Si prefieres no usar esta extensión, te recomendamos incluir las siguientes líneas en tu archivo `.vale.ini`:

```ini
[formats]
mdx = md

[*.mdx]
CommentDelimiters = {/*, */}

TokenIgnores = (?sm)((?:import|export) .+?$), \
(?<!`)(<\w+ ?.+ ?\/>)(?!`), \
(<[A-Z]\w+>.+?<\/[A-Z]\w+>)

BlockIgnores = (?sm)^(<\w+\n .*\s\/>)$, \
(?sm)^({.+.*})
```

Para usar los comentarios en el documento de Vale, utiliza comentarios de estilo MDX `{/* ... */}`. Si usas la opción `CommentDelimiters = {/*, */}` en tu [configuración](https://vale.sh/docs/keys/commentdelimiters), Vale interpreta automáticamente estos comentarios durante el linting. Esto significa que puedes aprovechar fácilmente las funciones integradas de Vale, como omitir líneas o secciones.

```mdx
{/* vale off */}

Este texto será ignorado por Vale

{/* vale on */}
```

Si decides no usar `CommentDelimiters` pero aun así usar los comentarios de Vale, debes envolver cualquier comentario de Vale dentro de comentarios de MDX `{/* ... */}`. Por ejemplo:

```mdx
{/* <!-- vale off --> */}

Este texto será ignorado por Vale

{/* <!-- vale on --> */}
```

Estas etiquetas de comentario no son compatibles dentro de los components de Mintlify, pero pueden usarse en cualquier lugar en el nivel base de un documento.
