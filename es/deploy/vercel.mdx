<div id="verceljson-file">
  ## archivo vercel.json
</div>

El archivo `vercel.json` define cómo se crea y se despliega tu proyecto. Se ubica en el directorio raíz y controla varios aspectos del despliegue, incluidos el enrutamiento, las redirecciones, los headers y la configuración de compilación.

Usamos la configuración `rewrites` para enrutar mediante proxy las solicitudes desde tu dominio principal hacia tu documentación.

Las reescrituras asignan las solicitudes entrantes a diferentes destinos sin cambiar la URL en el navegador. Cuando alguien visita `yoursite.com/docs`, Vercel obtendrá internamente el content de `your-subdomain.mintlify.dev/docs`, pero el usuario seguirá viendo `yoursite.com/docs` en su navegador. Esto es distinto de las redirecciones, que enviarían a los usuarios a una URL completamente diferente.

Puedes personalizar la subruta con cualquier valor que prefieras, como `/docs`, `/help` o `/guides`. Además, puedes usar subrutas con varios niveles, como `/product/docs`.

<div id="repository-structure">
  ## Estructura del repositorio
</div>

Los archivos de documentación deben organizarse dentro del repositorio para que coincidan con la estructura de la subruta que elijas. Por ejemplo, si quieres que tu documentación esté en `yoursite.com/docs`, debes crear un directorio `docs/` con todos los archivos de documentación.

<div id="configuration">
  ## Configuración
</div>

Para alojar tu documentación en una subruta personalizada con Vercel, añade la siguiente configuración a tu archivo `vercel.json`. Este ejemplo utiliza `/docs`, pero puedes reemplazarlo por cualquier subruta:

```json
{
  "rewrites": [
    {
      "source": "/docs",
      "destination": "https://[subdomain].mintlify.dev/docs"
    },
    {
      "source": "/docs/:match*",
      "destination": "https://[subdomain].mintlify.dev/docs/:match*"
    }
  ]
}
```

* **`source`**: El patrón de ruta en tu domain que activa la reescritura.
* **`destination`**: A dónde se debe enviar la solicitud mediante proxy.
* **`:match*`**: Un comodín que captura cualquier segmento de ruta después de tu subruta.

Para obtener más información, consulta [Configuring projects with vercel.json: Rewrites](https://vercel.com/docs/projects/project-configuration#rewrites) en la documentación de Vercel.

<div id="using-external-proxies-with-vercel">
  ## Uso de proxies externos con Vercel
</div>

Si usas un proxy externo (como Cloudflare o AWS CloudFront) delante de tu despliegue en Vercel, debes configurarlo correctamente para evitar conflictos con la verificación de domain de Vercel y la emisión de certificados SSL.

Una configuración incorrecta del proxy puede impedir que Vercel emita certificados SSL de Let's Encrypt y provocar errores en la verificación del domain.

Consulta los [proveedores compatibles](https://vercel.com/guides/how-to-setup-verified-proxy#supported-providers-verified-proxy-lite) en la documentación de Vercel.

<div id="required-path-allowlist">
  ### Lista de rutas permitidas obligatorias
</div>

Tu proxy externo debe permitir el tráfico a estas rutas específicas sin bloquear, redirigir ni aplicar un almacenamiento en caché agresivo:

- `/.well-known/acme-challenge/*` - Requerido para la verificación de certificados de Let's Encrypt
- `/.well-known/vercel/*` - Requerido para la verificación de domain de Vercel
- `/mintlify-assets/_next/static/*` - Requerido para los recursos estáticos

Estas rutas deben pasar directamente a tu despliegue de Vercel sin modificaciones.

<div id="header-forwarding-requirements">
  ### Requisitos para reenviar el Header
</div>

Asegúrate de que tu proxy reenvíe correctamente el Header `HOST`. Sin un reenvío adecuado del Header, las solicitudes de verificación fallarán.

<div id="testing-your-proxy-setup">
  ### Probar la configuración de tu proxy
</div>

Para verificar que tu proxy esté configurado correctamente:

1. Comprueba que `https://[yourdomain].com/.well-known/vercel/` devuelva una respuesta.
2. Asegúrate de que los certificados SSL se estén aprovisionando correctamente en tu dashboard de Vercel.
3. Verifica que la verificación del domain se complete correctamente.
